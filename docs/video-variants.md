# Three Competing Demo Video Concepts

All variants stay below three minutes, use native WebMCP for the final recording, keep the live capability panel visible, and show one uninterrupted Run → Approve → Commit → Reset cycle.

## Variant A — The capability that did not exist

**Hook:** “There are five tools. The dangerous one does not exist.”

Opening:

- 0:00 show the count 5 and “Write capability absent.”
- 0:04 show the natural-language request.
- 0:08 run five live tools.
- 0:18 hold “DRAFT — NOT SUBMITTED.”
- 0:22 approve.
- 0:26 show count 6 and the new one-time tool.

Strengths:

- WebMCP is visible before the product domain needs explanation.
- The absent/present distinction is memorable.
- The first judging tie-break criterion is answered first.

Risks:

- Needs concise context so the sixth tool does not feel arbitrary.
- Requires a clean native recording with the capability panel readable.

## Variant B — A prompt is not permission

**Hook:** “Telling an agent not to submit is an instruction. Removing the submit capability is authority.”

Opening:

- 0:00 show the prompt ending “Don't submit anything until I approve.”
- 0:06 contrast prompt text with “Write capability absent.”
- 0:11 execute the five preparation tools.
- 0:21 show exact draft.
- 0:25 approve and reveal the sixth tool by 0:30.

Strengths:

- Best explanation of the safety problem.
- Strong product and policy language for non-WebMCP judges.
- Connects human approval directly to capability design.

Risks:

- More narration before the live protocol reveal.
- Can sound abstract if the count transition is not immediate.

## Variant C — One prompt, five specialists, one human key

**Hook:** “One request coordinates five structured tools. A human unlocks the sixth for one exact action.”

Opening:

- 0:00 show the full service-operation dashboard.
- 0:05 introduce fragmented context.
- 0:10 run the five tools and narrate each.
- 0:22 show the selected provider and draft.
- 0:27 approve; sixth tool appears just before 0:30.

Strengths:

- Strongest operational and impact narrative.
- Makes multi-tool orchestration easy to follow.
- Familiar to service/commerce judges.

Risks:

- Resembles other booking/commerce demos until approval occurs.
- “Specialists” can over-anthropomorphize deterministic tools.

## Decision

Choose **Variant A**, with Variant B's single sentence as the second beat.

Why:

- It reaches the differentiating WebMCP fact fastest.
- It makes the 5 → 6 → 5 visual the hero rather than dispatch logistics.
- It is hardest to confuse with a conventional CRUD, search, booking, or fake-chat demo.
- It aligns with the tie-break priority on WebMCP Leverage.

Final opening line:

> “There are five live WebMCP tools. The dangerous one does not exist. A prompt can ask an agent to wait, but only human approval changes its actual capability surface.”
